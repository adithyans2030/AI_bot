Okay so today let's go over binary search trees again since a couple of you asked about the deletion case last week. Remember the core property: for any node, everything in the left subtree is smaller, everything in the right subtree is bigger. That's the whole trick that makes search fast. So if I'm looking for the value 42 and I'm sitting at a node with value 50, I know immediately I only need to look left, I never have to check the right side at all. That's what gets us that O(log n) behavior, same idea as binary search on a sorted array, we're cutting the search space in half at every step, at least when the tree is reasonably balanced.

Insertion is basically the same walk. You start at the root, you keep comparing and going left or right, and the moment you hit a null pointer, that's where the new node goes. It just becomes a new leaf. Nothing else in the tree has to move.

Deletion is where people get tripped up, so let's slow down here. If the node you're deleting is a leaf, trivial, just remove it. If it has exactly one child, you just splice that child up into the deleted node's spot. The annoying case is when the node has two children. What we do there is find the in-order successor — that's the smallest value in the right subtree, so you go right once, then keep going left as far as you can. You copy that successor's key up into the node you wanted to delete, and then you go delete the successor instead, and the successor is guaranteed to have at most one child so that deletion is easy.
